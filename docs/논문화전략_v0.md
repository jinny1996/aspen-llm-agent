# 논문화 전략 v0

작성: 2026-10-08 / 상태: 초안 (사용자 검토 전). 증류탑(RADFRAC) 지원은 이번 범위에서 제외하고 추후 추가.

## 1. 풀어야 할 문제

1. 기존 연구 대비 노벨티와 contribution이 있어야 한다.
2. "Claude 등 AI 툴로 MCP 없이도 Aspen 바이브코딩이 되지 않나?"라는 반응이 나오면 안 된다.
3. 단순 프로그램/앱 개발처럼 보이지 않아야 한다 (포지셔닝과 스토리텔링).
4. 논문마다 정답(SI 등)이 있는 것이 아니므로 평가가 정답에 의존하면 안 된다.

## 2. 선행연구 지형 (읽은 범위 기준, 투고 전 체계적 문헌검색 필요)

| 갈래 | 대표 | 하는 일 | 암묵적 전제 |
|---|---|---|---|
| ① LLM을 시뮬레이터 인터페이스로 | Aspen MCP(SNU), ACS Copilot(I&ECR 2026), 멀티에이전트 Aspen 자동화(Hedengren 계열) | 자연어로 Aspen 조작 | 사용자가 사양을 다 준다 |
| ② 텍스트/PFD → flowsheet 생성 | ETH Text-to-flowsheet, CRAFTS(arXiv 2608.01369) | flowsheet 생성, 빈 DoF는 최적화(ETH)·DoF 개수 검사(CRAFTS)로 채움 | 수렴하면 성공 |
| ③ 모호성·가정 처리 | SINTEF(arXiv 2603.00214) | 모호함 탐지 → 가정 로그/질의 | 시뮬레이터 기본값은 로그에 안 남음 (본인들이 열린 문제로 명시) |
| ④ 오류 복구·경험 축적 | CRAFTS 디버그, ChipMEM(2609.27067), MemGuard(2608.21867) | 실패 수리, 검증된 경험 저장 | 목표는 실행 성공률 |

공통점: 평가 지표가 수렴 여부·성공률·한 사례 수치 일치. "최종 모델의 각 값이 왜 그 값인가"를 묻는 연구는 확인되지 않음. ACS Copilot은 누락 사양 5개를 나열만 하고 항목별 해결 기록이 없음(SI 확인).

미열람: CRAFTS 부록, ETH SI, ChipMEM 원문.

## 3. 포지셔닝

**문헌 기반 모델링은 미결정(under-determined) 역문제다.** 논문은 필요한 자유도 R 중 일부 S만 보고하고, 나머지 G = R \ S는 문서에 없다. 기존 시스템은 G를 채운 결과가 수렴했는지만 본다.

**핵심 문장: 수렴은 충실성의 증거가 아니다 (Converged ≠ Faithful).** 모델은 돌아가지만 그 안의 값 중 얼마가 논문에 근거하고 얼마가 조용히 만들어졌는지 아무도 모른다. Claude 바이브코딩이 쉬워질수록 이 문제는 커진다 → "Claude로도 되잖아" 반박을 오히려 문제의 근거로 쓴다.

**논문 유형:** 측정 + 방법 논문 (시스템 논문 아님). 서사 순서는 발견 → 지표 → 방법.

**하지 않을 주장:** "더 정확한 모델을 만든다"(정답 없이 증명 불가), "Aspen을 자동화한다"(바이브코딩과 경쟁하는 자리).

**한정된 주장:** 근거 없는 값을 드러내 사람에게 묻고 기록한다. 그 값들이 결과를 실질적으로 바꾼다는 것을 민감도로 보여 위험의 크기를 입증한다.

## 4. 스토리 5박자

1. 관찰: LLM 에이전트로 문헌 기반 Aspen 모델이 높은 "성공"률로 만들어진다.
2. 문제: 성공 = 수렴일 뿐, 논문에 없는 값 G가 어떻게 채워지는지 기록도 검증도 없다. 조용한 오류 분류체계 제시.
3. 측정: 기존 방식에서 근거 없는 값이 얼마나 생기고, 결과를 얼마나 바꾸는지 (정답 불필요 지표). ← 헤드라인
4. 방법: 근거 유형 분류 + 시뮬레이터 유효값 감사 + 영향도 기반 질문.
5. 함의: 문헌 기반 자동 모델링의 평가는 수렴률이 아니라 충실도 지표를 써야 한다.

## 5. Contribution (3개)

1. **문제 정의와 오류 분류체계.** 조용한 오류 유형: 단위/기준 오류, 타 유닛 값 차용, 변수 이식(예열 400 °C → 반응기 T), 대안 중 임의 선택, 시뮬레이터 기본값, 날조·부실 인용. 기존 실행 로그(방향족화 13건, 메탄화 16건, 질량 유량 오류 63건)에서 도출.
2. **정답 불필요 충실도 지표 세트.**
3. **결정적 감사 방법(EDC).** LLM 자기보고 대신 규칙·인용 검증·시뮬레이터 읽기로 판정, 영향도 기준 질문 선택.

내림(부록/한 줄): MCP, Gradio, 에이전트 루프, Part1/2/3 상세, RAG 복구. D(검증 기반 경험 누적)는 ChipMEM/MemGuard가 메커니즘을 선점했으므로 future work로만 언급.

## 6. 평가 지표 (정답 불필요)

| 지표 | 정답 필요? | 내용 |
|---|---|---|
| 근거 추적성 | 아니오 | 값이 논문 텍스트로 추적되는 비율, 인용이 값을 실제로 지지하는 비율, 날조 인용률 (원문만으로 결정적 검사) |
| 유효값 감사 | 아니오 | 지정값 vs Aspen이 실제 사용한 값(COM 읽기)의 불일치. 단위 되돌림, 기본값 치환 |
| 실행 간 불안정성 | 아니오 | 같은 논문 N회 실행 시 값이 갈리는 정도. 논문이 결정하지 않은 값의 지문 (예: 펌프압 1.5/2.0/2.85) |
| 결과 민감도 | 아니오 | 근거 없는 값을 그럴듯한 범위에서 흔들었을 때 핵심 출력(전환율, 열부하 등) 변화 |
| 논문 보고 결과 일치 | 부분 | 본문에 스트림 표·핵심 수치가 있는 논문에 한해 보조 |

주의: SI 기반 정답은 케이스 B에서 사용자가 SI를 직접 붙였기 때문에 있는 것이며 일반적 평가 수단이 아니다. 사례 연구(E4)로만 사용.

## 7. 실험 계획

| 실험 | 질문 | 비교 |
|---|---|---|
| E1 현황 측정 | 기존 방식에서 근거 없는 값이 얼마나 생기는가 | B0(바닐라 Claude+Aspen 도구, 프롬프트만), B1(B0+"가정을 전부 나열하라"), B2(우리 파이프라인, EDC 끔) |
| E2 영향 크기 | 그 값들이 결과를 얼마나 바꾸는가 | 민감도 분석 |
| E3 방법 효과 | EDC가 조용한 오류를 얼마나 드러내고 질문 부담은 얼마인가 | 베이스라인 + 질문 상한 K 변화 |
| E4 사례 연구 | 정답이 있는 논문에서 사용자 응답이 오류를 실제로 고치는가 | 케이스 B (보조 증거) |

## 8. 데이터

- 논문 8~12편, 사양 완전도 스펙트럼(완전 / 일부 공백 / 큰 공백). 지원 블록(RGIBBS 등)으로 재현 가능한 공정만.
- A·B·C는 파일럿 용도. **규칙을 동결한 뒤 새 논문은 전부 held-out.**
- 새 논문에서 새 오류 유형이 더 안 나오는지(포화) 확인 → 분류체계 일반성 근거.

## 10. Go/No-Go 파일럿 (가장 먼저)

논문 A·B·C에서 B0/B1/B2/Ours를 3회씩 실행, 정답 불필요 지표만 비교.
- **Go:** B0/B1에서 근거 없는 값·조용한 오류가 눈에 띄게 나오고 Ours가 드러냄.
- **방향 수정:** B1이 비슷하게 잘 드러내거나, 근거 없는 값의 민감도가 작아 "그래서 뭐?"가 되는 경우 → 축을 불안정성(재현성)이나 상호작용 효율로 이동.
